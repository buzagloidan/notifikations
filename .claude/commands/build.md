# Notifikations — Project Context

**Notifikations** (display name: *Notifikations*) is a privacy-first iOS/Mac Catalyst app that lets users send push notifications to their own devices via a webhook URL — no account required.

---

## Repo layout

```
notifications/
├── ios/          SwiftUI app (XcodeGen → Xcode 16, iOS 18+, Swift 5.9)
├── worker/       Cloudflare Worker — backend API  (Hono + TypeScript)
└── website/      Static marketing site            (plain HTML/CSS, Cloudflare Pages)
```

## Architecture

### Privacy model
- No user accounts. The server never sees raw secrets — only SHA-256 digests.
- **deviceSecret** (`ntf_dev_…`) — per-device, generated on first launch, stored in Keychain and synced to CloudKit private DB.
- **userSecret** (`ntf_usr_…`) — shared across all of a user's devices, sourced from CloudKit.
- Both secrets are hashed (`sha256Digest` extension on `String`) before leaving the device.

### Webhook flow
```
caller → GET/POST api.notifikations.com/api/v1/:secret
         ↓
  worker hashes :secret → looks up in KV
  • deviceDigest hit  → send to that device
  • userDigest hit    → fan-out to all registered devices
```

Supported payload fields: `message` (required), `title`, `subtitle`, `sound`, `open_url`, `image_url`, `interruption-level`, `filter-criteria`.
GET requests pass fields as query params; POST accepts JSON or plain-text body.

### Monetization
- RevenueCat SDK (`RevenueCat` + `RevenueCatUI` SPM packages, pinned to 5.67.0).
- Entitlement ID: `"Notifikations Pro"`.
- 14-day free trial is enforced **server-side** in the worker (`TRIAL_DAYS = 14`, keyed off `createdAt` on the device record).
- Pro status is granted/revoked via a RevenueCat server-to-server webhook (`POST /api/v1/webhook/revenuecat`); clients can only *revoke* (`isPro: false`) via `/api/v1/update-status`.

### Cloudflare Worker (`worker/`)
- Runtime: Hono on Cloudflare Workers with `nodejs_compat`.
- KV namespace binding: `NTF_KV` (id `727eac7e21cd4c0ea5b494d5c4e5b42d`).
- Route: `api.notifikations.com/*`.
- APNs: JWT auth via `.p8` key stored as Wrangler secrets (`APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_KEY_P8` base64-encoded, `APNS_BUNDLE_ID`).
- RC webhook secret: `RC_WEBHOOK_SECRET` Wrangler secret.

KV key schema (see `worker/src/lib/kv.ts`):
```
device:{deviceDigest}       → DeviceRecord { deviceToken, label, createdAt, isPro?, rcUserId? }
userDigest:{userDigest}     → JSON array of deviceDigests
token:{deviceToken}         → { userDigest, deviceDigest }
rcUser:{rcUserId}           → deviceDigest
```

### iOS app (`ios/`)
- Project file generated by XcodeGen from `ios/project.yml` — **do not hand-edit the `.xcodeproj`**.
- Bundle IDs: `com.idanbu.notifications` (app), `com.idanbu.notifications.NotificationService` (extension).
- Team: `ZADSZ6HP53`. Code signing: Automatic.
- CloudKit container: `iCloud.com.idanbu.notifications`.
- API base: `https://api.notifikations.com` (see `ios/Notifications/Config.swift`).

## Build commands

### iOS

```bash
# 1. Copy secrets config (first time only)
cp ios/Config/Secrets.xcconfig.example ios/Config/Secrets.xcconfig
# Fill in REVENUECAT_API_KEY_DEBUG and REVENUECAT_API_KEY_RELEASE

# 2. Regenerate Xcode project after editing project.yml
cd ios && xcodegen generate

# 3. Open in Xcode and build/run normally
open ios/Notifications.xcodeproj
```

### Worker

```bash
cd worker
npm install          # first time
npm run dev          # local dev with wrangler
npm run deploy       # deploy to production
```

Secrets are set once via:
```bash
wrangler secret put APNS_KEY_ID
wrangler secret put APNS_TEAM_ID
wrangler secret put APNS_KEY_P8      # base64 -i AuthKey_XXXXX.p8 | tr -d '\n'
wrangler secret put APNS_BUNDLE_ID
wrangler secret put RC_WEBHOOK_SECRET
```

### Website
Static files in `website/` — deploy via Cloudflare Pages (no build step).

## Worker API surface

| Method | Path | Purpose |
|--------|------|---------|
| POST | `/api/v1/register` | Register device + link to user |
| DELETE | `/api/v1/unregister` | Remove device |
| POST | `/api/v1/rotate` | Rotate device secret |
| POST | `/api/v1/rotate-user` | Rotate user secret (all devices) |
| POST | `/api/v1/update-status` | Client revokes Pro status |
| POST | `/api/v1/webhook/revenuecat` | RevenueCat S2S webhook (grant/revoke Pro) |
| GET/POST | `/api/v1/:secret` | Send notification webhook |
